SECTION 01
三大关键趋势洞察
T01

编排本身也是智能的体现：从模型编排到 harness / Agent 编排

编排的核心收益，是以更低成本、更高可靠性、更短路径组织智能。Sakana Fugu 把多模型编排训练成一个 foundation model；Harvey 将“何时求助、求助哪个模型”的一部分逻辑内化进自研法律模型；Cognition Devin Fusion 用 sidekick 模式和动态中程路由，在 成本降低 35% 的同时维持 frontier 级性能。编排层正在从手写 workflow，走向能随模型、工具和任务变化自适应调整的智能层。
Sakana FuguHarveyDevin FusionDatabricks OmnigentCodex / Ona

Sakana Fugu：模型编排成为模型能力

Fugu 本身是一个小模型，学习动态协调 Gemini、GPT、Claude 等智能体池完成复杂任务，而非依赖单一模型。fugu-mini 延迟优先，fugu-ultra 性能优先。关键启示不是“多叫几个模型”，而是编排策略本身可以被训练、评估和产品化。

编排层成为新的能力边界

Harvey：workflow 与自研模型分工

Harvey 的 worker-advisor harness 让开源 worker 处理主干推理、起草与工具调用，前沿模型作为稀疏顾问处理高质量要求子任务。自研模型吸收步骤拆解、工具调用、子 Agent 协调与求助判断，但 workflow 仍承担用户侧可交付、可复核的法律工作产品。

Devin Fusion：multi-model harness 的经济性

Cognition 通过 frontier Agent 与低成本 sidekick Agent 并行、动态路由和持久化可缓存上下文，将 FrontierCode 成本从每任务 5.12 美元降至 3.00 美元，得分保持在同等水平。模型选择不只发生在任务开始前，也发生在执行过程的中段。

Databricks / Ona：Agent 运行控制层

Databricks Omnigent 与 OpenAI 收购 Ona 指向同一件事：Agent 需要统一运行、沙箱、策略、审计、成本预算和跨会话持续工作。未来的差异化可能不是单个 Agent 多聪明，而是多模型、多 harness、运行时策略、协作环境和数据上下文如何共同被组织。

T02

Agent 编排之外：群体智能何时真正涌现

多 Agent 系统当前更多强调成本与能力的动态平衡，但它未必能突破最前沿模型能力边界。真正值得追问的是：多个主体互动后是否会产生新的判断、新策略或新行为模式？DeepMind 播客指出“认知单一文化”与智能体合谋风险；Stanford 等研究发现自组织 LLM 团队无法稳定利用专家，团队共识化甚至会拖累专家表现。群体智能的关键，可能不是增加 Agent 数量，而是制度性地维持认知多样性、激励差异和少数派信号。
Cognitive MonocultureExpert LeveragingMulti-Agent DebateSimileSocial Simulation

认知单一文化与相关性风险

如果数百万 Agent 都基于少数几个基础模型，它们可能在相同刺激下做出高度相似决策，放大相关性风险。Agent 还可能通过环境间接协调，因此需要考虑反合谋机制，而不仅是单点安全过滤。

专家识别不等于专家利用

Stanford、Emory 等研究发现，自组织 LLM 多 Agent 团队即使知道谁是专家，仍会把专家与非专家观点折中平均，最高造成 37.6% 以上性能损失。开放讨论不自动带来智慧，默认民主协商可能稀释专家信号。

社会模拟需要差异化上下文

现有多 Agent debate 的收益更像多轮纠错和交叉检查，不等于天然获得类似真实人类的观点差异。真正的社会模拟需要记忆、偏好、身份、行为数据、激励差异和信息差异，而不只是 prompt 出乐观派、悲观派或专家角色。

Simile：从市场研究到社会实验基础设施

Joon Sung Park 的 Simile 把真实人群数据压缩成 synthetic population，用于反复测试产品、定价、政策与系统性后果。关键不是模拟单个用户喜不喜欢，而是多个模拟体互相影响之后，系统会发生什么。

T03

Agent 时代的数据孤岛：从业务系统叠加到个人隐性知识

过去的数据孤岛主要发生在 CRM、ERP、工单、财务、代码仓库与文档系统之间。Agent 时代，孤岛进一步扩展到个人层面与协作层面：员工如何思考、如何提问、如何改稿、如何做判断、如何在 Slack/会议/文档中协作。这些隐性知识正在成为 Agent 的上下文输入。Claude Tag、Meta 员工数据采集与 Databricks Omnigent 都说明，企业 AI 的竞争焦点正在从“接入业务系统数据”扩展到“沉淀上下文、行动轨迹和判断过程”。
Claude TagMeta DataOmnigentSECIEngramNon-human Identity

Claude Tag：频道级上下文与共享 Agent 身份

Claude Tag 的核心是频道级上下文。它记忆所在频道的信息，基于这些信息规划未来任务，成为持续理解团队工作流的协作成员。共享身份降低 adoption 门槛，也放大权限、记忆和责任归因问题。

Meta：专家数据成为训练稀缺品

从记录员工键鼠操作、发布 Autodata、重新分配工程师到限制 Claude 与 Codex，Meta 的动作反映出一个判断：能训练 Agent 的专家行为、判断与验证任务数据比公开代码更稀缺。

Omnigent：打通 Agent 行动轨迹

Omnigent 的战略意义不只是统一 coding agents，而是把个人工作流中的 prompt、tool calls、搜索路径、失败路径和人机反馈纳入组织级治理与复用。它试图建立 Agent 时代的统一控制面板。

知识螺旋的新缺口

SECI 模型里，组织创新来自显性知识与隐性知识的持续转化。Agent 若无法捕捉协作中的隐性知识，就只能做文档检索和流程执行，很难真正替代“知道如何判断”的人。
