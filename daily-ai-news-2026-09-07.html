OpenAI 首席科学家 Pachocki 发文：没有任何实验室有资格全速规模化，呼吁建立共享安全栏

OpenAI 首席科学家 Jakub Pachocki 发表长文《An Alien Mind》，核心判断是：目前没有任何实验室在对齐与监控上取得足够进展，能够以最高速度负责任地继续规模化；他期望"自愿减速"成为常态，直至建立由第三方审计机构或国际组织共同执行的共享安全栏，并呼吁各国政府把 AI 国际协调列为首要任务。他判断当前进展速度可以持续到递归自我改进（RSI），未来几年的能力跃迁将越来越多由 AI 自身驱动；OpenAI 将继续构建对齐与监控方案和防御系统，必要时单方面暂停进一步规模化。技术层面，文章区分两类对齐训练：目标导向 RL（平均有效但脆弱，以 OpenAI–Hugging Face 事件为例）与预训练概括（缺乏对优化压力的鲁棒性）；并透露 OpenAI 评估显示思考链监控的可靠性正在下降（模型更擅长推理自身推理、预训练让模型不语言化推理也更聪明），正在探索直接访问网络内部的监控器。Pachocki 称 GPT-6 Astra 是首个受益于 OpenAI 长期对齐投入的模型、较 GPT-5.6 Sol 对齐显著提升，但警示可泛化对齐的进展可能追不上通用智能的提升。

Insight by AI 这是 OpenAI 研究领导层罕见地把"减速条件"白纸黑字化——把自家 Preparedness Framework 与 Anthropic RSP 类承诺推向"第三方强制安全栏"，等于主动邀请外部约束；结合同期维基事件披露框架，OpenAI 正在从"能力叙事"切换到"治理叙事"。

Insight by AI 用自家一手数据把"AI 研究加速"公开化，是 OpenAI 论证 Agent 不仅改造产品端、也改造科研端生产关系的标志性动作；这份数据也将成为外部评估"AI 做 AI 研究"进度的罕见基准。

研究关注

LLaDA-Image：以全开源训练配方构建强图像生成器

论文 LLaDA-Image 提出一个统一框架，将从零训练的 6B 参数 Diffusion Transformer 与基于 LLaDA2.0-Mini 扩散语言模型的冻结视觉-语言理解模块结合。生成流水线包含 2.2 亿样本，其中 9800 万为真实图像；DiT 全程使用无参数 RMSNorm 与 Muon 优化器以兼顾效率与可扩展性。作者进一步将其蒸馏为 LLaDA-Image-Turbo，可在 2–4 步采样内快速推理。在 Qwen-Image-Bench 上，LLaDA-Image 在英文与中文榜分别取得 53.53 与 53.38 的总体分，刷新开源模型最优成绩。作者同步发布模型权重、训练代码与详细训练配方。

Insight by AI LLaDA-Image 以"图像-only 预训练先行、再做多模态对齐"的两阶段路线刷新开源 SOTA，并在配方、权重、代码三件套上全开源，体现了开源生成模型正从"放权重"升级到"放完整工艺"。
HuggingFace Daily Papers / arXiv

RoboTok：以互联网规模人类视频为机器人学习检索灵巧操作示范

RoboTok 将给定的人类操作视频作为查询，从海量网络视频中检索可用于训练灵巧机器人策略的相关人类示范。系统从 3D 手部轨迹学习一个隐式运动空间，并基于估计的以人为中心的参考帧表达轨迹，从而在不同相机视角、场景外观和遮挡条件下比较操作行为。该团队在检索基准与下游机器人策略表现上对 RoboTok 进行了评估。论文结果显示 RoboTok 能检索到更相关的操作示范并提升下游任务成功率。

Insight by AI 用人类手部姿态轨迹隐空间做跨视角跨外观对齐，把 YouTube 类互联网视频变成可增量索引的机器人训练语料，为长尾任务绕开真实机器人数据采集的高成本。
HuggingFace Daily Papers

Terminal-Universe 把 Agent 轨迹回放为可执行环境并合成新任务

Terminal-Universe 是一个把终端 Agent 轨迹转为可复用训练环境的框架，其思路是回放轨迹中记录的文件操作把每个被修改前的文件恢复，从而得到一个部分工作区，再由补全 Agent 补齐缺失文件与依赖。在此基础上，它会重构原始意图任务并合成全新任务，并沿广度与深度两个方向扩展任务集：在广度上挖掘相关环境之间的有向依赖关系，合成跨多个代码库的查询；在深度上把单轮查询扩展为多轮会话，通过用户 Agent 模拟迭代反馈与需求修正。该框架被应用于公开终端 Agent 轨迹，产出 3.73 万个足以支撑训练的任务环境；在该语料上对 Qwen3.5-27B 进行监督微调后，模型在 Terminal-Bench 2.1 的单轮性能提升 11.9 分，在 EvoCode-Bench v2 的多轮 MT@4 性能提升 13.8 分。

Insight by AI 论文将稀缺瓶颈从"轨迹数据"转移到"可执行环境"，并通过轨迹本身反向重建环境，把单次演示放大成可重查询、可验证的训练资源，这一思路对 Agent 后训练数据供给具有结构性意义。
HuggingFace Daily Papers / arXiv

SE-RRM：符号等变让 200 万参数小模型做结构化推理

针对数独、ARC-AGI 等对神经网络仍然困难的推理问题，该论文在循环推理模型（RRM，含 HRM/TRM 家族）基础上引入符号等变层，在架构层面强制置换等变性，保证符号或颜色置换下解完全一致。SE-RRM 在 9×9 数独上超越先前 RRM，且仅用 9×9 训练即可外推到 4×4 与更大的 16×16、25×25（现有 RRM 无法外推）；在 ARC-AGI-1/2 上以仅 200 万参数和少得多的数据增强取得有竞争力的表现。

Insight by AI 与"堆规模"路线相反，这项工作显示把问题对称性烧进架构能让极小模型获得大模型缺的结构化泛化，对 ARC-AGI 这类考察抽象泛化的基准是重要先验。

BCIT：自主后训练系统要学会"何时不复用"过往经验

自主 LLM 后训练系统会积累大量过往更新证据，但一次更新的效果依赖其父模型、数据与训练阶段——把过去的成功当作无上下文的复用许可会浪费算力，甚至让劣质子模型污染后续训练轨迹。该论文将此形式化为"条件经验迁移"问题，提出 BCIT（Boundary-Calibrated Intervention Transfer）：把观测效果绑定到来源上下文、检查适用条件、对命名硬冲突直接否决、必要时通过有界训练试验获取当前状态证据。在一个 4B 模型跨金融推理、text-to-SQL、函数调用三类适配的实验中，等预算下 BCIT 授权的有害更新更少、最终模型质量更高。

Insight by AI 随着 AIRA、AlphaEvolve 类自主训练系统增多，"经验库"本身会成为新的故障面；这篇论文把经验授权当独立问题处理，是自主后训练走向可靠的一块拼图。

X讨论

Perplexity 披露 GPU 嵌入推理全栈：CUDA Graphs + Rust 三层架构

Perplexity 公开了支撑其搜索与 API 平台的嵌入模型（pplx-embed）推理基础设施：Ivy（Rust HTTP 网关，负责 tokenization、请求拆分与负载均衡）、Tulip（Rust gRPC 推理服务器，调度与组批）、ROSE（Python 推理引擎，模型前向与 CUDA graph 管理）。核心工程点包括：全模型 CUDA graph（把 token 数分桶到 64/256 的倍数、懒捕获以摊薄启动成本）、LazyTensor 异步结果追踪（重叠 CPU 与 GPU 工作）、以及与 LLM 推理共享内核（batch 嵌入≈compute-bound prefill、在线嵌入≈memory-bound decode，pplx-embed 与 Qwen3.5 解码走同一套 kernel）。注意力内核按形状在 FlashAttention 4 与 FlashInfer 3 间按需选择，基准对比 vLLM v0.22.0 报告了延迟与吞吐优势。

Insight by AI 值得注意的是方向判断：嵌入推理的 GPU 侧已高度收敛，优化空间转移到运行时与 harness（CUDA graph 管理、异步追踪、负载拆分）；Rust+Python 混合栈正在成为推理服务的标配。
Perplexity Blog / @perplexity_ai

人类如何从 AI 学习：围棋选手 130 万手决策的证据

该研究分析职业围棋选手 130 万手落子决策，发现人类是在观察到 AI 的推理过程（如 KataGo/Leela Zero 类引擎展示的胜率图与变化图）之后、而非仅仅看到 AI 的落子动作之后，才开始做出更像 AI 的决策。对照分析显示：有 AI 程序使用权的棋手在获得 AI 推理过程访问后决策质量显著提升，无 AI 访问权的棋手则没有变化。结合 X 上的讨论：棋手质量跃升发生在开源引擎（含推理过程可视化）普及之后，而非 AlphaGo 闭源夺冠之时——推理过程的开放性是人类学习的关键变量。

Insight by AI 对 AI 协作的直接启示：只给结论（action）不解释（reasoning），人类难以从模型学到东西；可解释、可展示推理过程的工具才真正改变人类行为，这为 CoT/推理透明度的产品价值提供了难得的自然实验证据。
eScholarship / @thesephist

Turing Post 撰文：递归自我改进尚未发生，症结在策略与记忆

The Turing Post 发文讨论递归自我改进尚未实现的原因，将其归结为两类问题。文章指出，现有 AI 擅长按既有方案执行和迭代，但难以更新驱动系统改进的“方法”，缺少对路径的重新思考。另一类问题来自记忆维度，AI 已具备相应技能与知识，但仍存在记忆层面的限制。

Insight by AI 把瓶颈拆成「策略不重写」与「记忆不可持续」两端,意味着 RSI 的下一程可能由元学习/记忆外化类产品驱动,而非更大参数规模本身。
@theturingpost

OpenAI Codex 团队发文：GPT-6 Astra 时代需要重写 Skills 与 AGENTS.md 指令

OpenAI Codex 团队的 Eric Provencher（@pvncher）发文《Rethinking skills and prompts for GPT-6 Astra》，核心判断是：过去为"扶稳"弱模型积累的臃肿指令正在变成负资产。Skills 层面，描述过多过长时 Codex 会截断描述、模型反而看不清该选哪个，描述互相矛盾或"pick me"式措辞会误导加载；官方已更新 $skill-creator 指引——描述尽量短、根文档做最小路由以实现渐进式披露、少写菜谱式细则（模型已能理解模糊性）。AGENTS.md 层面，要求每次编辑前读全仓文档是浪费上下文，GPT-6 Astra 会自主跑测试，旧指令导致冗余测试。行为差异上，为旧模型加的"先问再做"强限制会过度约束 Astra（它会把边界当真、提前停工），且 Astra 比 GPT-5.6 Sol 更早收工待审——应在任务开始前定义完成标准。文末建议让 Astra 按此文对项目做一次指令审计。

Insight by AI Agent 最佳实践正从"scaffolding 补短板"转向"给强模型松绑"：模型每次升级，指令集都要跟着迁移审计，"指令债务"成为新的维护成本；对多模型共用的仓库，指令还需按模型分层（帮 Sol/Luna 的约束可能拖累 Astra）。
@pvncher
