ARC-AGI-3 深度分析
5/3 · GPT-5.5 和 Opus 4.7 的推理缺陷被解剖
ARC Prize Foundation 分析了 160 次交互运行，揭示 三种系统性推理错误：
  • GPT-5.5 0.43% vs 人类 100%——233x 差距
  • Claude Opus 4.7 0.18%——556x 差距
  • Gemini 3.1 Pro 0.37%
三种错误模式：
  • Opus：错误模式强加——将熟悉模式强行套用到不熟悉任务
  • GPT-5.5：假设放弃过早——形成正确假设后过早放弃
  • 两者：探索不足——系统性未能充分探索环境
这不是「分数低」，而是「推理模式根本不同」——当前模型所有推理建立在「压缩已知模式」上，ARC-AGI-3 要求的是「在无指令环境中从零发现规律」。

IKP 论文（5/1）
反推闭源模型参数量 · 核心结论成立，数字不可靠
Pine AI 首席科学家单人论文，利用信息论下界通过 1,400 道跨 7 个冷僻度等级的事实问答测量模型知识容量，反推参数量。
  • 核心结论成立（LessWrong 独立复现确认）：事实记忆与参数量的对数线性关系斜率稳定在 ~0.15；Densing Law 确实不成立；scaling 远未饱和
  • 但具体数字不可靠：代码存在 per-tier flooring（论文声称未做），~10% 高难度题目有歧义或答案错误
  • 修正后：GPT-5.5 从 ~9.7T 降至 ~1.5T（范围 ~1.5T-9.7T）；Opus 4.7 从 ~4T 降至 ~1.1T（范围 ~1.1T-4T）
  • 具体参数量对方法论选择极度敏感，不应作为可靠数字引用

「Benchmark 饱和」的表述可能掩盖了真实结构：GPQA 饱和不是因为模型接近「智能上限」，而是因为它测的是「压缩已知知识」——这个任务对当前模型基本完成了。ARC-AGI-3 近乎零分也不是因为模型「不够聪明」，而是因为它测的是「在无指令环境中从零发现规律」。用「饱和」描述这两类现象可能掩盖关键差异：在「探索式推理」这个维度上，scaling 的有效性尚未得到验证。
判断 2
ARC-AGI-3 的两种失败模式指向不同的推理缺陷：Opus 4.7 的问题是过度压缩（把不熟悉的任务强行塞进熟悉模式），GPT-5.5 的问题是不压缩（无法收敛到稳定假设）。Mythos 如果在 ARC-AGI-3 上同样接近零（几乎可以确定），暗示当前 LLM 范式在「探索式推理」上可能存在结构性限制——修复是否需要新的训练目标或架构，尚未有定论。
判断 3
开发者生态出现「模型能力 ≠ 产品体验」的第一次真实分叉：OpenAI 解除 Azure 独占（模型可上 AWS Bedrock / Google TPU）降低了接入门槛，但 @theo 的实测发现「GPT-5.5 更聪明，但 Opus 的意图理解和 taste 更好」，且 GPT-5.5 放进 Claude Code harness 后在 PostTrainBench 上未能打赢 Opus。这可能部分来自 harness 优势，也可能部分来自 Opus 在 agent 场景上的特定能力，两者难以拆分——但无论归因为何，对开发者来说结果相同：最强模型 ≠ 最佳体验。Copilot 6/1 转按用量计费后，@theo 展示了 $221/15 messages 的真实账单。三个变化同时发生（多云分发 + 用量计费 + 真实账单冲击），第一次提供了市场价格弹性的真实数据——开发者在「最强模型」「最佳体验」「最具性价比」之间的三角选择，下月就能看到。
判断 4
Sakana Fugu 的 SWE-Pro 54.2% 是本周最重要的未验证信号：如果第三方验证，意味着「训练更好的调度器」在编程任务上可以替代「训练更强的模型」。但目前只有 Sakana 自述数据，GPQA Diamond 和 LiveCodeBench 同样缺乏第三方验证——这两条线都需要等，不应基于未验证数据做结构性判断。
判断 5
Grok 4.3 的低价或许是 L1 结构优势 + accuracy 取舍，不是模型效率突破：拆解 $1.25/$2.50 的定价——xAI 自有 Colossus 集群（100K+ H100）不付云厂商溢价（L1 成本优势）；non-hallucination -8 分、Vending-Bench 2 个重大回退说明低价伴随 accuracy 代价（具体是蒸馏/量化/对齐取舍，原因未公开）。是否低于成本线取决于 xAI 未公开的算力利用率——如果 Colossus 利用率不满，边际成本可能确实很低；如果接近满载，则大概率在亏损抢开发者生态。护城河不在模型层（L2），在算力基础设施（L1）和定价策略——「性价比」需要更精细的定义。
判断 6
在 Agent 场景下，系统层（L3）的边际收益正在放大：三条独立证据线均来自 Terminal-Bench（agent 完成终端任务）——AHE 论文通过自进化 harness 把 Terminal-Bench 从 69.7% 提到 77.0%（+7.3pp），超 Codex-CLI 71.9%，且可跨模型迁移；Mason Drxy 仅通过 prompt 调优把 gpt-5.2-codex Terminal-Bench 从 52.8% 提到 66.5%（+13.7pp）；Sakana Fugu 7B 编排器超越池中所有单模型。但需要注意：目前所有证据集中在 Agent/编程这一个场景，Terminal-Bench 恰好是 harness 影响最大的场景——换成数学推理（FrontierMath）或知识问答（GPQA），harness 的边际贡献可能完全不同。从单场景推「L2→L3 竞争焦点全局迁移」跨度太大，更审慎的说法是：在 Agent 场景，harness engineering 可能比模型选择更能决定效果上限。这与 SemiAnalysis 观察到的利润向模型层集中是不同维度的现象——SemiAnalysis 说的是产业链利润分配（谁赚更多钱），这里说的是特定场景下的竞争要素权重（什么决定产品效果），两者不宜直接串联。
