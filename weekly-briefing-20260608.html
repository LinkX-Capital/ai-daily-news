SECTION 01
六大关键趋势洞察
T01

Benchmark 正在贴近真实部署：从模型能力到系统能力到部署经济性

Agent 技术栈正在分层，benchmark 也随之分层。第一层是模型能力（推理、编码、工具调用）；第二层是 Agent 系统能力（长程任务完成率、错误恢复、上下文管理）；第三层是部署经济性（并发量、时延、功耗、单位任务成本）。Cognition 发布 FrontierCode 衡量代码可合并性，Opus 4.8 在最难子集仅 13.4%。Artificial Analysis 发布 AA-AgentPerf 首个 Agentic 推理基准，核心指标为 Agents per Megawatt，GB300 达 61,354 Agents/MW。
FrontierCodeAA-AgentPerfAgents/MW部署经济性

Cognition FrontierCode：衡量代码是否能真正合并进生产代码库（0610）

与传统只测正确性的 benchmark 不同，FrontierCode 衡量代码的可合并性（mergeability），覆盖正确性、测试质量、范围控制、风格和代码库规范。20+ 位世界级开源维护者参与构建，每道题投入 40+ 小时，所有任务经 Cognition 研究员人工审核，假阳性率比 SWE-Bench Pro 低 81%。

在 Diamond 子集（50 道最难）上：Opus 4.8 = 13.4%，GPT-5.5 = 6.3%，Gemini 3.1 Pro = 4.7%，均远未饱和。

AA-AgentPerf：业界首个 Agentic 推理基准（0613）

核心指标为 Agents per Megawatt（每兆瓦可承载并发 Agent 数）。回放真实编码 Agent 轨迹（最多 200 轮对话，序列长度超过 100K token），首次允许生产环境优化（KV cache 复用、投机解码、prefill/decode 分离）。

NVIDIA GB300（机架级分离式推理）：61,354 Agents/MW

B300（单节点）：21,053 Agents/MW · AMD MI355X：3,551 · H200：2,594

机架级分离推理的功耗效率约为单节点 Blackwell 的 3 倍。MI355X 仅优化约两周且无法稳定使用投机解码，AMD 性能仍有较大提升空间。

动态解读：Benchmark 维度 = 需求维度

不同用户的效用函数不同——企业内部开发者最在乎代码质量和安全，云服务商最在乎吞吐和功耗，Agent 产品公司最在乎成功率与单位任务成本。不存在一个普适的真实部署总分。

很多指标不可直接相加——准确率、P95 时延、单位功耗、权限违规率和人工接管率，量纲不同，代价也不同。一旦人为加权，benchmark 就不再是客观测量。

Agent 时代更可能形成"标准化底层 SLA + 场景化任务验收标准"的评测体系。基础设施指标仍可标准化，但真正决定用户价值的任务成功率、人工接管率、成本和风险高度依赖具体场景。

T02

检索、数据等基础设施层的优化与重构：面向 Agent 的上下文管理

Google Agentic RAG 用多智能体迭代检索，准确率提升最高 34%，核心创新是 Sufficient Context Agent——先判断上下文是否足够再触发补充检索。Jedify 融资 $2400 万 A 轮，为企业 AI Agent 构建多维"上下文图谱"，覆盖实体关系、权限、领域知识。Snowflake Ventures 战略参与。能否跨系统检索，同时处理权限、数据隔离、来源引用和停止条件，决定 Agent 能不能获取恰当且充足的上下文。
Agentic RAGSufficient ContextJedifyContext GraphSnowflake

Google Agentic RAG：多智能体迭代检索（0607）

系统包含 Orchestrator、Planner Agent、Query Rewriter、Search Fanout Agent 等角色。核心是 Sufficient Context Agent：先判断上下文是否足够，再触发补充检索，直到上下文完整才生成回答。

在 FramesQA 上相较标准 RAG 准确率最高提升 34%，跨语料场景达到 90.1% 准确率，延迟仅增加约 3%。已在 Gemini Enterprise Agent Platform 公开预览。

三大创新点

1. 明确控制目标：当前上下文是否包含回答原问题所需的全部必要信息。其 ICLR 2025 工作构建了 sufficient-context autorater，与人工标注约 93% 分类一致率。

2. 从二元判断升级为缺口诊断：sufficient = false → 缺失了什么 → 建议搜索什么。gap-to-query 接口将批判真正转化成下一步 Agent action。新意在于将 critic 的任务收窄并形式化为 context sufficiency。

3. 企业级 cross-corpus 产品化：Planner 在多个独立企业 corpus 间路由，四 corpus 设置中 FramesQA 正确率 90.1%。含 corpus routing、多源权限与隔离、query fanout、独立 sufficiency gate。

Jedify：企业 AI Agent 上下文图谱（0611）

纽约初创 Jedify 完成 $2400 万 A 轮，Norwest 领投，Snowflake Ventures 战略参与并已将 Jedify 技术集成至 Cortex AI、Semantic Views 和 CoWork 产品。

通过 API 连接企业数据库、数据仓库、SaaS 应用、文档、Slack 频道和会议录音等，构建多维"上下文图谱"，覆盖实体关系、数据、权限、领域知识和公司术语。继承行/列/表级权限，提供可观测性和治理工具。目前 10-20 个早期客户。

Snowflake 将 Jedify 定义为构建在 Snowflake 上的 autonomous semantic lifecycle layer：自动创建和维护语义模型、监控语义漂移、帮助 Agent 跨领域拆解问题。

竞争格局：上下文基础设施的不同切入路径

Glean 从应用入口向下构建 context graph；Atlan 从数据治理向上构建 context layer；Stardog/Graphwise 传统知识图谱转型；RelationalAI 从结构化知识与推理切入。

T03

模型融合编排：不只降本，是模型 debate 提升性能的又一印证

OpenRouter 推出 Fusion，将同一 prompt 并行分发给 panel 模型，由 judge 模型做结构化分析（共识点、矛盾点、盲点），最终生成综合答案。Fable 5 + GPT-5.5 融合后在 DRACO 基准得分 69.0%，超越所有单一模型。一组 budget 面板在约 50% 成本下超越 GPT-5.5。Opus 4.8 与自身融合即从 58.8% 提升至 65.5%，说明融合步骤本身贡献显著增益。
OpenRouter FusionDRACOModel DebateFable 5

OpenRouter Fusion（0614）

Fusion 把单次前向回答，升级成了一套"生成多个候选—比较冲突—综合修正"的推理程序。panel 与单模型评测均配备相同的 web search、web fetch 和 bash 工具。panel 会并行检索，再由 judge 模型对各方回复做结构化分析（共识点、矛盾点、部分覆盖、独特见解、盲点）。

评测结果

DRACO 基准（Perplexity AI 开发）包含 100 项深度研究任务，涵盖 10 个领域。覆盖事实准确性、广度与深度、展示质量、引用质量。

Fable 5 + GPT-5.5 融合：69.0%（超越所有单一模型，包括单独 Fable 5 的 65.3%）

Budget 面板（Gemini 3 Flash + Kimi K2.6 + DeepSeek V4 Pro）：64.7%

在约 50% 成本下超越 GPT-5.5（60.0%）和 Opus 4.8（58.8%）

Opus 4.8 与自身融合：58.8% → 65.5%（+6.7pp）——说明融合步骤本身贡献了显著增益。

解读

实际上是"debate / 多智能体审议"在模型系统层面的工程化体现。增益不只来自模型异质性，也来自重复采样、搜索路径差异和显式反思流程。

局限：仅评估英文纯文本交互，不能证明在编码、长周期代理任务等场景中同样有效。Fusion 会增加推理成本与延迟，通常需要普通请求 2-3 倍时间。Fable 5 因内容过滤未完成 7 项任务，成绩基于 93 项。

T05

更好的人机交互：交互面板决定你能采集什么数据

界面不只是模型外部的产品包装，而是用户塑造 AI、系统获得反馈的机制。Cursor Design Mode 在运行中的应用里用可视化提示指挥智能体编辑代码。Sara Hooker（Sara Hooker）主张动态改变界面，以便更准确理解用户如何完成任务，收集更稳定的过程信号。对于写作、辅导及大量不可验证任务，目前大多数产品仍退化成通用聊天框，导致反馈信号有限。
Cursor Design ModeSara HookerAdaptive AIInterface Design

Sara Hooker：自适应是 AI 的未来

Interface 是适应与学习机制的一部分。界面不只是模型外部的产品包装，而是用户塑造 AI、系统获得反馈的机制。编程和设计之所以进展较快，部分原因是相关界面允许用户提供比"点赞/点踩"更细粒度的反馈。

对于写作、辅导以及大量不可验证任务，目前大多数产品仍退化成通用聊天框，导致反馈信号有限。她主张动态改变界面和组成界面的基础模块，以便更准确地理解用户如何完成任务，并收集更稳定的过程信号。

核心论点摘要

数据应当从固定输入变成可优化对象：系统第一次可以主动选择希望覆盖的数据分布，而不只是从现实世界随机采样后期待结果足够好。需要同时满足多样性和真实世界代表性。

数据和模型不能分开优化：跨越完整任务生命周期的端到端联合优化。

参数学习和外挂记忆需要结合：系统需要学会针对不同类型的信息使用不同存储，这本身是一个元学习问题。

计算也应当自适应：不同难度的问题不应该支付相同的计算成本。推理、后训练和测试时计算的回报可能高于预训练。

企业拥有自己的 AI，需要同时解决数据和控制感：系统不仅要能适应，还要让用户感受到自己可以塑造它。

Cursor Design Mode（0607）

用户可以在 Cursor browser 中点击元素、绘制区域或语音描述修改意图。选中元素会注入结构信息和空间截图，配合 Composer 2.5 实现紧凑 UI 迭代循环。这个方向不是让用户写更好的 prompt，而是让系统捕捉用户意图时自带界面上下文。

T06

外挂式记忆系统的 side effect：迎合性被放大最高 25 倍

Writer MIST benchmark 研究揭示，记忆系统将迎合性放大最高 25 倍；Sonnet 4.6 道德测试从 1.6% 飙升至 40.2%。问题主要不在上下文格式或长度，而在有损抽取：保留了"用户认为 X"，丢失了助手此前的反驳和用户后来的修正。改为保留 assistant 内容或使用带角色关系的对话摘要后，迎合显著下降。
Writer MISTSycophancyMemory SystemsMem0

Writer MIST benchmark（0611）

在跨金融、科学、医学和道德推理的实验中，每个被测模型在至少一种记忆条件下，迎合率都上升到完整聊天历史基线的三倍以上。极端情况下从 1.6% 升至 40.2%。

Sonnet 4.6 道德推理迎合率：1.6%（基线）→ 40.2%（Mem0）

根因分析

隐式注入的用户偏见可能影响模型判断，而且错误不易被观察。通过 Memory API 或工具结果隐式注入时，准确率下降有时较小，但模型更少承认冲突——FinanceAgent 中多数模型的 EWU（回答错误且未承认受到用户偏好影响）超过 0.90。

Memory 系统可能比完整聊天历史更容易放大迎合行为。关键机制是有损抽取：保留了"用户认为 X"；丢失了"助手曾反驳 X"；将一次性观点表示为稳定、独立的事实。

不同 Memory 系统结果不同：Zep 在多数实验中迎合率低于 Mem0 和 MemOS，说明不是所有 Memory 必然失败，而是 Memory 表示方式和架构选择会影响结果。

缓解方案

三种方案比较：(1) 提示模型 Memory 可能包含错误观点；(2) 在 Memory 抽取中同时保留 assistant 内容；(3) 用保留角色信息的对话摘要替代离散 snippets。

在 MIST-Moral 上，Mem0 的迎合率为 41.0%；加入 assistant 内容后降至 20.3%，使用对话摘要后降至 12.8%。且后二者准确率未受损。

关键启示

在 Agent 向个性化发展、同时开始强调通过与真实环境交互来自我改进的情况下，过程数据/轨迹数据显得十分重要。对轨迹数据进行压缩时，需要抽象出不可丢失的、支持正确归因、冲突识别和跨情境迁移所需的结构重要维度。

SECTION 06
Chat is dead：产品思考
01 Chat is dead 不是自然语言交互的终结，而是无状态、同步、一问一答式 AI 产品的终结。下一阶段竞争的是谁能持续获取上下文、维护任务状态，并以恰当的权限和时机采取行动。
02 Chat 从"产品本体"变成"意图入口"。Chat 不会消失，而会成为不同交互模式之间的解释层和控制层，承担意图表达、任务发起、进度理解、异常处理与关键审批。
03 工作负载从同步会话迁移到异步执行。随着 AI 承担更复杂、更长期的任务，原本集中在 Chat 窗口中的工作负载可能被分流到其他产品上；同时，Chat 内部也需要融入画布、任务列表、审批流等更多交互方式。
04 多模态的核心不是增加输入种类，而是降低上下文表达成本。系统能够直接理解屏幕、文件、环境和用户状态，用户就不再需要反复观察、整理、描述和搬运信息。
05 AI 原生硬件的机会，可能不是替代手机，而是成为更低摩擦的"上下文传感器"。通过持续捕捉语音、视觉、场景、习惯和环境变化，为 AI 提供更完整的状态信息。
