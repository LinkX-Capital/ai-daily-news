fal 发布 H3 Max Director：首个原生连续实时前沿视频模型

fal 推出 H3 Max Director，定位为首个原生连续实时的前沿视频模型，支持动作控制的长篇生成。与 H3 Max 及其他视频模型不同，Director 生成单一连续视频流、随时间维持上下文，而不是把离散片段拼接成链。该技术支撑了 fal 的实验性无限 AI 直播（观众可实时交互并影响生成内容）。此前 fal 已基于 MiniMax H3 后训练出 H3 Max，主打快于实时的生成速度（RTF 低于 1），H3 Max Turbo 进一步做到 2 倍速、768p 每秒 0.01 美元。

Insight by AI 从"生成 5 秒片段"转向"维持上下文的连续视频流"，视频模型正在从素材工具变成可直播的实时媒介；动作控制+实时交互的组合直接指向新的内容与娱乐形态。

蚂蚁开源 Ling-3.0-flash 全家桶：VL 视觉、Sante 医疗、Fin 金融三连发

蚂蚁集团 AntLingAGI 连续开源三个基于 Ling-3.0-flash（124B 总参、5.1B 激活）的领域增强模型：Ling-3.0-flash-VL 增加视觉理解与视觉 agent 能力，覆盖视觉感知、STEM 推理、文档智能、多模态 agent、前端编码与医疗报告解读；Ling-3.0-flash-Sante（取法语 santé"健康"之意）面向医疗推理、专业医疗任务、深度研究与循证检索，在 MedXpertQA-Text、DiagnosisArena-MCQ、AFUMED-Drug、HealthBench Professional、BrowseComp 上有竞争力，宣称在开源模型中领先；Ling-3.0-flash-Fin 与金融机构和领域专家共同开发，支持信息检索、研究、估值建模与报告撰写，配套开源专家构建的金融搜索 agent 基准 FinFIRST，用原子化 rubric 同时评估答案与证据（如何搜索、处理时效性任务、组合来源、选择可靠证据、计算与可验证性）。

Insight by AI 在通用开源模型竞争白热化后，"开源底座+领域后训练+配套基准"成为差异化路径；FinFIRST 把评估对象从答案扩展到证据链，是金融 AI 可验证性的一种务实做法。

Claude用11天完成费马大定理端到端Lean形式化，由清华姚班校友发起

Anthropic 公布详情：这是费马大定理（FLT）的首个完整计算机可校验证明。由清华姚班校友、Anthropic 研究员 Tianyi Peng（其在 Columbia 的团队构建 AI 形式化工具）发起测试，Claude 在 11 天内大体自主完成：数十个 Claude agent 协作，产出 1300 万行 Lean 代码（约为 Mathlib 的 5 倍以上）、过程中证明 30,300 个定理（最终证明使用 29,500 个），遵循 Darmon-Diamond-Taylor 简化版 Wiles 证明路线，仅使用 Lean 三个标准公理。成功关键之一是 Peng 团队开发的开放协作平台 Prove2Me：以定理 DAG 组织任务、分离陈述与证明以加速编译、支持跨 agent 搜索复用。整个项目消耗约 60 亿输出 token（模型能力约当 Claude Fable 5.1）。此前社区估计此项形式化需数年（仅蓝图就 86 页）。审阅者 Kevin Buzzard（帝国理工，2024 年社区 FLT 形式化项目发起人）评价其为"非凡的自动形式化成就，AI 自动形式化产物已坚固到可在其上构建"。

Insight by AI 与近期 AI 产出新数学不同，此次突破在"验证"侧——当 AI 产出的证明超过人类审阅能力时，自动形式化可能是数学界跟上 AI 贡献的唯一可行方式；Prove2Me 式的协作脚手架（DAG+多agent）比单模型能力更像胜负手。

Bespoke Labs：用 SFT+RL 把开源模型 Inkling 个性化到单一代码仓库

Bespoke Labs 回答了一个实际问题：开源编码模型能否通过后训练在特定仓库上变得更好？以 fontTools 开源仓库为例，团队用 SWE-Smith 方法构造仓库专属任务（固定仓库状态+注入缺陷+测试评分器），先用强教师模型（Claude Opus 4.8）的 146 条成功轨迹做 SFT，再在 92 个新任务上用 14 项 rubric 引导的 GRPO 做 RL。结果：留出 fontTools 评测集通过率从基线 0% → SFT 52% → SFT+RL 57%；未参与训练的 SQLGlot 仓库也从 0% 升至 54%，说明仓库技能存在跨库迁移。通用能力未受损：Terminal-Bench 2.1 从 35.7% 升至 38.4%，SWE-bench Lite 从 53.6% 升至 56.7%，且输出 token 分别减少约 44% 和 35%。

Insight by AI 两个关键信号：SFT 贡献了绝大部分提升（52pp 中 RL 只加 5pp），说明教师轨迹是主杠杆；单仓库训练却能迁移到未见仓库，暗示"仓库个性化"学到的可能是通用的修 bug 技艺——若在更多仓库上成立，这条路线的性价比会远超预期。
Bespoke Labs / @AlexGDimakis

研究关注

反事实可模拟性：Tinker 检视两篇可解释性新论文

Thinking Machines 的 Tinker 团队发文讨论"你能否解释 LLM 行为"——判断标准是：能否预测 prompt 改变时输出如何变化（反事实可模拟性）。两篇新论文均用 Tinker 完成：CST（Counterfactual Simulation Training） 提出用"奖励能让模拟器准确预测模型在反事实输入上输出的 CoT"来训练，在 cue 类反事实监控上把监控准确率提升 35 个百分点（模型最大 235B），且发现用 LLM 改写不忠实 CoT 比 RL 单独训练便宜 5 倍；CHIVE 则构建 agent 流水线自动发现真实场景中的异常模型行为并用反事实 prompt 编辑生成数千条解释，意外发现所研究的常见可解释性技术对预测反事实行为没有任何提升，但用 CHIVE 实验结果做训练数据可泛化到多种分布外场景。

Insight by AI 两篇论文一个建设一个反思：CST 证明 CoT 忠实性可以被训练改善，CHIVE 则给现有可解释性工具泼了冷水——"解释"如果不能预测反事实行为，可能只是合理化的叙事。
@tinkerapi / CST / CHIVE

Random Attention：随机驱逐 KV cache，推理吞吐提升 32-43%

现有 KV cache 压缩方法共享同一范式：给每个缓存 token 打分、保留高分者。该论文证明选择信号几乎不贡献价值：Random Attention 完整保留 prompt、在每个注意力头内均匀随机驱逐，不做任何打分；在 4 个模型、6 个推理任务上匹配最强先验驱逐器，在 vLLM 部署中吞吐高出 32-43%。机制解释：prompt 才是 cache 中脆弱的部分（选择器的差距主要在于是否碰巧保留了 prompt）；而推理轨迹通过两级冗余自我保护——文本层（模型边推理边复述所需信息）和注意力头层（每个头保留自己的轨迹副本），因此随机抽取也足以保留模型所需内容。

Insight by AI 对长思维链推理场景的高价值结论：与其精细化打分，不如保住 prompt 后直接随机驱逐——更简单的机制反而更快，"推理轨迹自保护"的洞察可能改变整个 KV 压缩方向。
HuggingFace Daily Papers

WHALE：模型权重与 Agent harness 的交替联合优化

Agent 性能同时依赖模型权重和执行 harness 代码，单独优化任一侧都会被冻结的另一侧卡住。WHALE（Weight-Harness Alternating LEarning）交替执行两个阶段：在当前 harness 下更新模型（在线拒绝采样微调）、在更新后的模型上搜索更好的 harness（Meta-Harness），并用固定时长或自适应耐心规则决定切换时机。在 Qwen3.5-2B/4B 三个领域（搜索问答、数学推理、国际象棋谜题）上，WHALE 比 weight-only、harness-only 和 Fast-Slow Training 最高提升 4.15-24.38 个百分点（best mean@8）。实验还显示瓶颈侧会轮换：SearchQA 上 harness 搜索用更少 rollout 就追平 weight-only 峰值，数学任务则必须先更新权重 harness 搜索才有效。

Insight by AI 与同日的 HarnessDev 形成互补：一个证明 harness 是被低估的能力变量，一个给出权重- harness 联合优化的可行配方；对 Agent 团队的直接启示是——只调 prompt/harness 或只微调模型都可能在做局部最优。

Compile by Training：把自然语言规格编译成本地神经函数

该工作提出"以训练代编译"：将自然语言描述的文本处理函数编译成可复用的小型神经函数。编译期由教师模型生成任务专属样本，训练一个紧凑解释器的小 adapter；编译产物无需教师模型即可运行，可像普通软件一样存储、版本化与组合。在 FuzzyBench-Hard（Program-as-Weights 快速编译器零命中的子集）上达到 83.6% 语义准确率，代价是编译耗时约一分钟而非秒级。已部署为公开交互服务，并在多站点网页助手、语言控制 3D 虚拟形象、英-Claudish 双向翻译器中验证。该论文当前居 HuggingFace Daily Papers 榜首（310+ 赞，MLSys 类）。

Insight by AI 把"调用远程大模型"变成"编译一次、本地无限次运行的神经函数"，为高频重复文本处理提供了绕开 API 成本、延迟与供应商依赖的路径。

HarnessDev：将评测单元从任务输出转向可运行 Agent 基础设施

论文指出，Agent 能力日益依赖模型外的执行基础设施，即 Agent harness；仅调整 harness 而固定模型权重即可显著改变任务表现。作者提出 HarnessDev 基准，把评测对象从任务输出转向可运行基础设施，分 Creation（从最小种子构建完整执行系统）与 Evolution（基于下游执行反馈迭代修订 harness）两阶段。Creation 阶段覆盖六款创建者 LLM、四个领域、五个下游基准共 2207 个独立实例，结果显示在代码与搜索/研究任务上生成的 harness 仍显著落后于成熟人工参考，而在写作与机器学习实验任务上可匹配或超越，执行成本差异显著。

Insight by AI 把 harness 本身作为评测对象，能区分模型本身能力与执行层增益的来源；Evolution 阶段收益不稳定且跨模型迁移有限，说明 harness 与执行模型的耦合度比预想更高。

陶哲轩：AI 生成的解可能"污染"开放问题作为领域进步源头的价值

陶哲轩在 Mathstodon 发长文，以不可压 Navier-Stokes 方程全局正则性问题（及 Euler 对应问题）为例讨论 AI 求解开放问题的副作用：该问题本是"AI 辅助成功故事"最有希望的候选——AI 工具既可能解决问题、又为领域下一轮进展搭好舞台；但现在出现了一种日益现实的情景——主要由 AI 生成的解答出现，却以污染该问题作为进一步进展源泉的方式。他同时指出该正则性问题的直接物理应用价值有限：计算流体力学已高度成熟（如大气科学中广泛部署），理论上保证正则性或构造 blowup 反例对天气/气候建模方式不会带来根本改变。

Insight by AI 与费马大定理形式化形成一周内的绝佳对照：一边是 AI 把"验证"问题解决掉（FLT），一边是陶哲轩警告 AI 可能"解决"问题但摧毁其激励结构（NS）——开放问题的价值不止在答案，还在人类沿解题路径发展的技术；当答案可以被 AI 直接给出时，数学界需要重新设计激励机制与评估方式。
