01 / Data assets

数据饥渴 — both for RL & 模型预训练

核心判断

数据交易正从“文档”转向可还原工作的真实轨迹，其价值取决于能否保留任务上下文、行动、反馈与结果，而不只是数据量。

公开语料解决“知道什么”，但 Agent 还需要理解任务如何完成、哪里出错、什么结果才算好；企业代码、任务记录与跨系统轨迹因此正从运营残留物变成训练资产。

工作过程开始被定价

02 / Scaling

Scaling 不再只有参数旋钮

唐老师分享与研究访谈共同指向：优质数据、后训练和长程交互，可能比继续增加参数带来更高边际收益，但还不是普适定律。

Deep dive展开阐释：Scaling 如何从单一参数扩张转向多轴配置
02 / Scaling

下一单位资源，应该投向哪一条扩展轴？

「唐老师的 token」提供全生命周期成本与多变量 Scaling 的框架；训练侧 Researcher 访谈则从大规模训练工程出发，说明数据、Infra 与架构必须协同验证。两份材料共同指向：模型规模没有失去价值，但不再是唯一旋钮。

相关研究 唐老师的 token：补充数据与后训练增益 ↗ NV infra 训练侧访谈（内部参考）↗

参数 × 数据协同

Scaling Law 不等于持续堆参数。参数规模需要与训练数据、算力分配和部署方式一起看；当长期推理成本占主导时，更小但训练更充分的模型，也可能拥有更优的全生命周期成本。

后训练正在数据化

Agent、Coding 等能力的瓶颈，越来越落在真实任务数据、长轨迹、反馈质量与训练信号设计上。许多后训练改进，本质上同时是在解决数据采集、筛选和组织问题。

规模验证不可跳过

小模型上的有效方法不一定能直接扩展到超大模型；收敛、显存、速度和工程复杂度会改变边际收益。规模越大，Architecture–Infra Co-design 与数据能否被有效吸收越重要。

任务决定最优旋钮

知识覆盖、复杂推理与长程交互可能分别更依赖容量、有效计算深度、post-training、RL 或推理时计算。真正的问题，是在当前模型阶段和任务目标下，下一单位资源投向哪里收益最高。

边界：训练侧访谈仅作内部研究参考；其中的经验比例与个别模型判断不作为统计事实。具体最优配比仍取决于模型架构、任务、部署规模与成本假设。

03 / Boundary

如何采、如何用好还在探索中

真实业务中的操作、交互与结果已经显现价值，但采集、授权、清洗，以及如何转成可靠训练信号，仍没有标准答案。

02

更低处理成本，不等于风险消失

结构化事件更容易形成连续工作时间线，但会损失部分视觉环境；键入内容与网页文本仍可能进入摘要，官方明确提示长期记忆会增加 prompt injection 风险。

权限边界采集范围与长期记忆需共同治理
!

资产不等于训练授权。公司拥有系统和工作成果，不自动意味着员工、客户与合作方同意将内部通信用于模型训练。数据清洗越彻底，越可能破坏工作流因果关系；保留关系越完整，隐私与重识别风险越高。

数据市场仍需回答的四个问题

  • 权利：代码、通信、客户数据和员工行为分别由谁授权？
  • 加工：真实数据用于识别分布、合成相似训练集，还是直接进入训练？
  • 定价：数据量之外，应如何衡量跨平台可追溯性、反馈质量与行业稀缺性？
  • 治理：如何支持删除、更正、差分隐私与用途限制，而不破坏训练价值？

02 / Learning loop

从购买智能到积累智能：企业需要 Learning Loop

核心判断

企业真正需要拥有的不是某个 API 或一组静态权重，而是把通用智能持续塑造成组织能力的 Learning Loop。

TML 的价值不只是训练基础设施，也不建立在“更私密或更便宜”上；关键是能否把企业历史、偏好与判断方式持续沉淀进系统。

01 / Heterogeneity

异质性来自组织，而不是模型

同一套 API 不会自动产生竞争优势；难复制的是组织长期形成的判断习惯、协作方式，以及带有路径依赖的因果经验。

02 / Layers

组织智能必须分层沉淀

动态状态留在 context、memory、RAG 与 workflow；稳定且跨场景复用的隐性判断，才可能进入权重。

03 / Loop

真正的资产是 Learning Loop

权重、记忆和评测都只是组件；壁垒在于能否把 Experience 经 Evaluation 持续转化为 Adaptation。

01 / EXPERIENCE

经验发生

AI 做了什么、人如何修改、真实结果如何，以及任务在哪个上下文中发生。

02 / EVALUATION

定义组织认为什么叫好

评价对象不只是模型输出，而是人与 AI 共同构成的工作系统；再区分噪声、个人偏好与稳定组织判断。

03 / ADAPTATION

改变系统

更新 context、memory、workflow、tools 或权重，让下一次行动真正不同。

权重、memory 与 eval 都只是组件；真正稀缺的是把每轮业务实践持续转成下一轮系统改进输入的机制。
两条组织适应路径

不是所有知识都该参数化：客户收入、项目进度、权限等动态状态适合留在 context、memory、RAG、数据库与 workflow；长期稳定、跨场景复用且难以显式表达的判断习惯，才可能内化进权重。两条路径共享的前提是，AI 不能永远以“没有组织历史”的通用模型身份进入企业。

03 / Embodied scaling law

具身智能 Scaling Law：从规模预训练走向现场适应

核心判断

具身 Scaling 的观察指标正从“会多少任务”扩展到“适应多快、迁移多远”。

GEN-1.5 报告新任务适应成本下降；Dyna-2 报告人类视频规模可能提升跨本体迁移。

01 / Generalist

适应成本正在成为新的观察指标

GEN-1.5 从极少梯度步进一步走到零梯度 Physical In-Context Learning；单示范平均成功率 59%，少样本适应后达到 83%，但尚不能把变化单独归因于预训练规模。

G1

关键产出不只是成功率，而是 adaptation cost 随迭代下降

Generalist 记录的新任务适应从数百个梯度步降到数十步、1 分钟数据配合 1 步，最终出现零梯度的上下文适应。10 步后权重变化不到 0.15%，更像调用和轻量重组已有能力，而不是重新学习一套表征；不过跨代变化同时包含数据、算力、架构与算法迭代，尚不是单变量 Scaling 曲线。

02 / Dyna

人类视频规模正在映射到机器人迁移表现

Dyna-2 报告：人类视频预训练从 1K 扩展到 1M 小时后，模型在未见机器人本体与任务上的离线动作预测持续改善；少量机器人数据后训练后的实体表现也延续了这一方向。

01 / 离线零样本跨具身扩展

D1 · 实验如何控制

团队从同一人类第一视角操作视频库中构建 1K、10K、100K 与 1M 小时的嵌套子集，仅在人类数据上预训练，再直接评估 39 个未见机器人任务；预训练阶段不接触机器人轨迹，也不做人类—机器人对齐或机器人微调。

D2 · 得到了什么结果

随着预训练规模扩大，机器人离线数据上的动作预测误差单调下降、准确率单调上升，并在 10K—100K 小时之间出现拐点。这里验证的是离线动作预测，不是实体机器人的零样本任务成功率。

02 / 少量后训练后的实体机器人表现

Dyna-2：实体机器人平均标准化得分

公司自报 · 各任务使用不超过 10 小时机器人数据后训练

从 1k 到 1M 小时，团队报告实体机器人平均标准化得分由 20% 升至 53%；曲线与任务数字均为公司口径。

D3 · 规模收益延续到实体任务

在 14 项实体任务上采用相同后训练流程、每项任务使用不超过 10 小时机器人示教数据时，平均标准化得分由 20%（1K）升至 53%（1M）。锁箱钥匙旋转在 100K 小时及以下为 0%，到 1M 小时达到 90%；双五指拧瓶盖使用约 10 分钟遥操作数据后训练，在 1M 模型上达到 50%。这些结果属于少量后训练后的迁移，不是零样本部署。

03 / 底层机制：世界建模与视频轴

D4 · WAM 为什么不同于 VLA

Dyna-1 是以动作预测为中心的 VLA，Dyna-2 则采用世界—动作模型 WAM；但机制证据来自 Dyna-2 内部消融，而不是跨代比较。联合预测未来视频与动作的 Joint 版本在 39/39 个任务上优于 Action-only，只有继续加入额外纯视频的 Video co-training 才呈现稳定的跨具身 Scaling。更稳妥的解释是：在 Dyna-2 的设定中，世界建模与纯视频增量共同构成关键训练信号。

D5 · 无标签视频成为新的 Scaling 轴

固定 5 万小时带动作标注的人类视频后，把额外无标签视频从 0 扩至 1K、10K、50K 小时；再固定 25 万小时动作数据，加入 25 万与 75 万小时无标签视频，两组留出机器人数据上的离线评估指标都单调改善。这意味着机器人预训练可能不必完全受限于昂贵的动作标注。

证据边界：上述离线曲线、实体任务结果与消融实验均来自 Dyna 团队技术报告，仍待第三方复现。当前最有解释力的证据，是固定带动作标注的人类数据、只增加无标签视频后，机器人评估仍持续改善。

03 / Synthesis

两类信号的证据强度不同

Generalist 更像跨代能力趋势，Dyna 更接近数据规模与迁移表现的对照；两者的关键数字仍来自公司自报，均需 OOD 测试和第三方复现。

对称与重复结构：人类行为数据天然包含连续、相似的动作模式。例如安装家具时，前一颗螺栓的操作可以成为 physical prompt，引导模型完成后一颗螺栓。

失败轨迹带来恢复能力：如果训练数据完整保留“失误—尝试—继续”的过程，模型在测试时更可能学会从错误中恢复。关键不是把数据过度处理得只剩成功示范，而是保留失败与纠正。

UMI 可能是更有潜力的采集范式：人通过手持机器人式夹爪直接操作环境，比 VR 或外骨骼 teleop 更容易保留精细动作、微调技巧与触觉反馈。

评测边界：当前示范任务仍较简单；Physical In-Context Learning 能否成立，还取决于测试任务与训练分布之间的距离。

以上观点仅针对 GEN-1.5，用于解释 Physical In-Context Learning 的可能机制；不是对 Dyna-2 的评价，也不是独立实验验证。

07 / Research notes

重点案例研究与观点分享

两篇材料值得单独展开：Engram 回答“组织记忆如何成为可学习的产品层”，Anthropic 回答“模型公司会把平台边界推到哪里”。

重点案例研究 Engram

AI 的学习型记忆层：让组织经验不必每次从头读取

Engram 的核心主张：模型真正的价值不在于更强的通用智能，而在于能持续理解、内化并调用特定团队或个人不断变化的上下文。
旨在解决的问题：找到一种训练算法，能够让模型吸收任意量的数据，并且不断优化自身性能。针对记忆层而言，要解决的难题是，什么值得记住，什么应该内化到模型权重。

01 / Boundary

记忆与学习是一体两面

动态事实继续留在工具、RAG 与上下文中；稳定的工作方式、组织关系和跨资料关联，才值得转化为可复用能力。

02 / Addressing

瓶颈不只是存储，而是寻址直觉

模型不仅要搜到文档，还要知道该搜什么、去哪里找，以及用户没有问但与任务真正相关的内容。

03 / Learning

持续学习缺失的是离线消化

在线互动之后仍需离线消化、探索与评估，再把有效经验回写为下一次可以调用的能力。

我们的分析

能力价值：让模型形成跨任务、跨文档的主动关联，并利用通用模型留下的 3–6 个月窗口持续学习，将组织经验逐渐沉淀为可复用能力。

成本价值：以前期训练与离线计算，换取后续更少的上下文输入、检索和重复推理。Engram 判断，在合适场景下可将推理 token 消耗降低两个数量级。

当前探索方向：Engram 团队正在并行研究上下文压缩、数据检索、LoRA、合成数据、长上下文与记忆架构，并尝试把文档、交互和反馈转成训练信号，通过监督微调、强化学习与 on-policy distillation 等方法将部分上下文写入权重。

关键挑战：选择真正适合内化的数据，支持事实更新、更正与删除，并避免错误内化、数据污染和灾难性遗忘。

长期方向：重新连接研究与产品，理解泛化如何产生、哪些经验应进入权重，以及模型能否从多模态的世界交互中持续学习。

价值继续上移到 meta-harness

可靠执行逐渐标准化后，差异化会转向 token 预算、模型路由和多 Agent 编排，在智能、成本与速度之间动态分配。

03 / Moat

最后一公里在校验与上下文连通

单纯拥有 context 不是壁垒；结果校验逻辑、行业系统连接和预算策略，才决定 Agent 能否稳定交付。

我们的分析

1. 确定性机会：领域 harness 本身就是产品，优先关注法律、金融、医疗、制造等高验证场景；进一步的机会包括负责 token 分配、模型路由和多 Agent 编排的 meta-harness，以及把上下文、权限、主动性与审计封装起来的组织级 Agent 运营。长期价值可能属于帮助企业持续学习、积累智能资产的系统。

2. 选行业的标准：寻找“用户会想再多做一点”的 token 饥饿型行业——迭代循环强、任务复杂、上下文重、输出价值高，既能承受智能成本，又要求可靠交付。判断公式是：正确的上下文 + 正确的工具 + 合适的形态 = 实际价值。

3. 初创判断逻辑：先看壁垒位于技术栈哪一层，而不是看功能数量；模型接入层价值有限，领域校验、上下文连通和预算策略更值得关注。再判断能力是否会被平台顺手打包，以及任务价值能否覆盖 token 成本。能用“小模型执行 + 大模型规划 + 评估兜底”降低同等结果成本的团队，才有结构性优势。
