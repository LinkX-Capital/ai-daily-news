四、Benchmark 排名更新：用分层雷达看，而不是混成一个总榜

本期 benchmark 的写法要避免偏袒任何模型：Arena 是人类偏好与输出体验；AA Intelligence 是综合智能与成本；Agents' Last Exam 是长周期专业工作流；AA Coding Agent / DeepSWE / Terminal-Bench 是模型 + harness + 环境；SWE-Bench Pro 仍显示 Anthropic 系优势；BrowseComp / OSWorld 看浏览和电脑使用；AA-Briefcase / GDPval-AA 看知识工作交付。只有把这些榜单分层，才能看清模型前沿真正发生了什么。

Benchmark 结论

  • 不要合成一个“总冠军”。不同 benchmark 衡量不同前沿：Arena 看偏好，AA 看综合智能与成本，ALE 看长周期工作流，DeepSWE / Terminal 看真实工程，GDPval / Briefcase 看知识工作交付。
  • GPT-5.6 的真正变化是 Pareto frontier。Sol 接近最高智能层并在 agent / browse / coding 上强势，Luna 把可用智能压到低价区间，缓存规则让长上下文 agent 成本更可预测。
  • Anthropic 仍有关键强项。Fable 5 在 AA Intelligence、Arena 顶部、SWE-Bench Pro 和知识工作 rubric / analytical quality 上仍是重要参照。
  • Meta Muse Spark 1.1 是低价第二梯队变量。它在 AA Index、SciCode、HLE、Omniscience 和 Arena 进入可比较区间，但不应被写成 frontier leader。
  • coding agent 的排名正在平台化。Codex、Claude Code、Devin、Grok Build、Cursor 轨迹和验证器会越来越影响 benchmark，而不只是底座模型。

本期竞争格局判断

  • 不要把周报写成模型粉丝榜。本期核心不是 GPT-5.6、Claude、Muse 或 Grok 谁“赢了”，而是前沿评价体系从单榜单变成多维任务雷达。
  • 重大模型发布的判断标准变了。必须同时回答：相对前代提升在哪、价格和缓存怎么变、是否改变 routing、是否改变工作流入口、是否改变 benchmark 的解释力。
  • 应用层机会正在从“接最强模型”转向“编排模型”。Sol / Terra / Luna、Muse Spark、Grok Build、LongCat MoE、Programmatic Tool Calling 都指向同一件事：模型选择、缓存、工具、agent 数量和验证器会成为核心基础设施。
  • 世界模型和非聊天型模型要放进前沿视野。Robostral、SensorFM、Seedream、Muse Image / Video 不是本期主战场，但它们代表前沿模型向真实世界状态、连续交互、垂直数据和生产工具迁移。
