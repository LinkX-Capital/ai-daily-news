## 保留/过滤
- 保留（以下全部保留，不要过滤）：AI/大模型、量子/脑机/核聚变/半导体、AI+行业、算力芯片、顶会论文、AI产业链融资/监管/IPO

## 信号类型与重要性（防误删 / 防误留）
**判断原则：优先「发生了一件具体的、大公司主导的新事」，而非「有人对某事发表评论 / 评估 / 推测」。标题响亮 ≠ 重要，措辞低调 ≠ 不重要。**

**强制保留**（即使措辞低调也不可过滤、不可降级）：
- 头部公司（OpenAI / Anthropic / Google / Meta / Microsoft / xAI / NVIDIA / 字节 / 阿里 / 腾讯 等）的**具体动作**：产品发布/上线、签约/合作/收购、融资到账、芯片或模型流片/发布
- 低调措辞仍是硬事件：`quietly launches` / `discussing` / `plans to` / 拟 / 或将 —— 只要**主体明确 + 动作具体**就保留

**降级或剔除**（即使标题响亮也压低权重）：
- 媒体二手评论/转述（机器之心、DeepTech、量子位 等"报道/解读"已有事物，非一手动作）
- 评估/评测/批判类论文（无新能力或新数据，如"XX 是否具备某能力""提出一种评估方法"）
- 推测性内容：讨论中 / preliminary / 可能 / 或将 / 据传 —— 无确认落点
- 同公司第二条：同一公司多条只留量级最高的，其余合并或剔除
- niche 初创融资（非头部、无标杆意义的小轮次）
- 无数据支撑的营销话术：「登顶 / 首个 / 最大 / 首选」缺少 benchmark / 金额 / 用户数佐证

**已知反例（勿重蹈）**：`Meta quietly launches Pocket`（产品上线 → 留）、`Anthropic discussing Samsung chip`（命名交易方 → 留）曾被误删；而 DeepTech/机器之心媒体二手、HF 社区投票的评估论文、OpenAI"讨论中"传闻曾被误留。

## 标题
- 主体+做什么+为什么重要，取最有影响力的动态
- **主体判断**：官方发布与第三方平台上线/评测分数同日出现时，标题主体是官方发布者——「StepFun 发布旗舰模型 Step 5 Preview：稀疏 MoE、支持 1M 上下文」✓，「StepFun 旗舰上线 OpenRouter」✗（平台宣布只是渠道消息，进 body）；仅当评测/榜单本身就是新闻（无同日发布、独家结论）才以评测机构为主体
- **融资/收购类标题必须带业务定语**：「AI 视频生成平台 Higgsfield 完成…」✓，裸写「Higgsfield 完成…」✗——读者不认识公司名时标题信息量为零
- **论文类标题 = 方法名 + 核心贡献 + 关键数据**（如「VeriHarness：智能体验证器提升长链路产出 6 分」），禁止「论文提出X」式泛模板开头，禁止用会议归属（ICML入选）代替核心区分点
- 动词匹配内容：论文→提出、博客→解析、数据→显示、产品→发布，禁止"发布"万能化
- 海外人名/公司保持英文，禁止感叹号/夸张词，禁止模糊称呼（"研究人员"→具体人名）
- 模型名规模标识与正文交叉验证（Ring-2.6-1T=万亿参数）

## Body
- **只写来源可验证的事实**，有几句写几句不凑数。关键数据加粗
- 海外人名/公司保持英文，禁止模糊称呼
- 禁止AI判断/推测，以下句式出现时移至insight：意味着/说明/标志着/趋势显示/这表明/反映出/是...的指标
- **事实密度**：模型类必须有benchmark数据点，融资类拆解资金构成，M&A类含金额/支付方式/市场反应
- **禁止无来源绝对判断**：首个/首选/核心地位/最大，除非原文明确支撑
- **来源归属**：hackathon项目→标注开发者非公司；媒体报道≠原创研究；只有官方blog/新闻稿才写"XX公司发布"
- **降级**：来源不可达→标⚠️+最小事实集，禁止凭标题臆测或AI推理凑数
- **格式**：禁止输出内部注释，arXiv编号只进来源链接不进body，URL机构标识与body机构名一致
- **论文类 body 开头**：用「论文提出/论文指出」或具体团队/机构名（如 Sakana AI 团队、商汤）开头；禁止「arXiv 论文」作主语或定语，「arXiv」只出现在来源链接 [arXiv](URL)；机构不是"研究者"，禁止「Meta等研究者」类机构人格化表达
